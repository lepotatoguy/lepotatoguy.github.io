HemeLB Improved Fork

Author: Joyanta Mondal Last Updated: September 30, 2026 Branch: fix/hemelb-improvements

lepotatoguy/hemelb on GitHub →

This is the easier path. The setup guides elsewhere on this site describe the older manual workflow (hand-editing setup.py, patching CGAL headers, running one-off scripts). This page describes a fork with fixes for those problems and a single install script. If you are installing HemeLB for the first time, start here.

What this is

HemeLB is a lattice Boltzmann solver for fluid flow in complex geometries, most often blood flow through vessel networks. This is a fork of it, lepotatoguy/hemelb, on the branch fix/hemelb-improvements.

fix/hemelb-improvements is now the fork's default branch, so a plain git clone gets it without needing -b. The fork's main branch is left identical to upstream hemelb-codes/hemelb, so nothing here changes what upstream does.

The fork adds a one-command installer for HemeLB, the geometry tool, and the Python tools; fixes a number of crashes and silent failures; and rewrites the documentation, which this page draws from. See the changelog for the full, checked list of changes.

Why use it

Compared with the older guides on this site:

  • One command, Scripts/install_hemelb.sh, installs HemeLB, the geometry tool, and the Python tools on macOS (Intel or Apple Silicon) and Debian/Ubuntu Linux. On Apple Silicon the geometry tool runs under Rosetta 2, because VMTK 1.5 exists only for x86_64; the script sets this up.
  • pip install './geometry-tool[gui]' works directly inside the conda environment. The old workarounds, commenting out the VMTK line in setup.py or running bodge-packages-for-setuptools.sh, are not needed.
  • Package versions are pinned, so an install today matches what was tested: every conda package to an exact build in the lock files (geometry-tool/conda-lock/), the main packages in geometry-tool/conda-environment.yml, and pip's build tools in geometry-tool/pyproject.toml.
  • Common mistakes now give a clear error message instead of a crash or an unclear error: a missing STL, a zero voxel size, a geometry with more inlets or outlets than the XML defines, a missing .gmy file, and asking for more MPI processes than the geometry supports.
  • The geometry tool warns when an inlet or outlet cannot reach the surface, lies beyond the end of the vessel, or when the seed point falls outside the surface. Before, these produced a geometry with a closed end and no warning; generation still finishes, but now you are told.
  • Checkpoints can be restarted with a different number of MPI processes than the run that wrote them.
  • The Python tools install and run on Python 3.12 and 3.13, not only the older versions.
  • Legacy .pro profiles are loaded with a restricted unpickler, so opening one cannot run arbitrary code.
  • Documentation is rewritten and checked against the current code: a start-here index with a glossary, a first-run walkthrough, a GUI walkthrough, and a build and run guide.

Requirements and tested platforms

Tested with the install script:

  • macOS 14, Apple Silicon (CI)
  • macOS 15, Intel (CI)
  • macOS 27, Apple Silicon (tested locally)
  • Ubuntu 24.04 x86_64 (CI and Docker)

Not tested:

  • Debian itself
  • The install script on Ubuntu releases before 24.04 (their default compiler may be too old for C++20; the main application itself is tested on 22.04)
  • Linux on ARM (no VMTK build exists, so the geometry tool cannot be installed there)
  • Distributions without apt (install the system packages yourself, then run the script with --no-system-deps)

You need git and an internet connection. Underneath the script, HemeLB itself needs a C++20 compiler (GCC 11 or newer, or AppleClang), CMake 3.13 or newer, and MPI 3.0 or newer. The geometry tool needs Python 3.8 to 3.11, because VMTK 1.5 is only built for those versions; the Python tools are tested on Python 3.8 to 3.13. Full detail, including the exact compiler, CMake, and MPI versions used in each tested environment, is in INSTALL.

Install

git clone https://github.com/lepotatoguy/hemelb.git
cd hemelb
Scripts/install_hemelb.sh

The same clone can also be written explicitly as git clone -b fix/hemelb-improvements https://github.com/lepotatoguy/hemelb.git; both get the same branch, since it is now the default.

On macOS, running git for the first time offers to install the Xcode Command Line Tools, which the build also needs; accept that first. (If they are still missing, the script opens the installer and stops; run it again once they are installed.) The script asks no questions of its own, though sudo or the Homebrew installer may ask for your password. By default it:

  1. Installs system packages (Homebrew on macOS, installing Homebrew itself if missing; apt packages on Linux, using sudo).
  2. Builds HemeLB and any dependency it cannot find into ~/.local/hemelb, then runs hemelb-tests.
  3. Creates a conda environment called gmy-tool with the exact tested package versions and installs the geometry tool and Python tools into it. If conda is not already installed, it installs Miniforge into ~/miniforge3.

On GitHub's CI runners the whole install takes about 5 minutes on Linux and 8 minutes on macOS. A laptop may take longer.

Useful options

Run Scripts/install_hemelb.sh --help for the full list. The ones you're most likely to want:

  • --prefix DIR: install HemeLB into DIR instead of ~/.local/hemelb
  • --jobs N: number of parallel build jobs
  • --env-name NAME: name of the conda environment (default gmy-tool)
  • --no-gmy-tool: build HemeLB only, skip the geometry tool and Python tools
  • --no-system-deps: skip Homebrew or apt, if you installed the required packages yourself
  • --no-tests: skip running hemelb-tests

If a conda environment with the chosen name already exists, the script stops. Remove it with conda env remove -n gmy-tool (or your chosen name) and run the script again.

Check that it worked

The script ends by printing these two commands. Run them in every new terminal, or add the first one to your shell profile (for example ~/.zshrc or ~/.bashrc) so you only need the second:

export PATH="$HOME/.local/hemelb/bin:$PATH"   # makes hemelb and hemelb-tests available
conda activate gmy-tool                        # needed for hlb-gmy-gui, hlb-gmy-cli, ...

Then check that each part is there:

which hemelb
hlb-gmy-cli --help
hemelb-tests

hemelb-tests prints All tests passed at the end if everything built correctly (the install script already runs this once, unless you passed --no-tests).

First run, in brief

Every HemeLB run follows the same four steps. This is a summary; the full walkthrough, with a working sample from the repository, is in Getting started.

  • 1. Geometry: turn a surface (.stl) and a profile (.pr2, with inlets, outlets, and a voxel size) into a geometry and configuration, with hlb-gmy-gui or hlb-gmy-cli. This writes a .gmy file (the voxelised vessel) and a .xml file (the simulation settings).
  • 2. Configuration: a generated .xml has no <properties> section, so HemeLB runs but saves nothing. Add one before the closing </hemelbsettings> tag, for example: 
    <properties>
  <propertyoutput file="whole.xtr" period="100">
    <geometry type="whole" />
    <field type="velocity" />
    <field type="pressure" />
  </propertyoutput>
</properties>
  • 3. Simulate: 
    mpirun -n 4 hemelb -in config.xml -out results
    The -out folder must not already exist. The run ends with Finish running simulation. and results land in results/Extracted/.
  • 4. Analyse: convert the saved extraction file to CSV: 
    hlb-dump-extracted-properties results/Extracted/whole.xtr whole.csv
    The CSV has one line per site per saved time step, with grid position, velocity (m/s), and pressure (mmHg).

Troubleshooting

  • Geometry file ... does not exist: the <datafile path="..."> in the XML is wrong. Relative paths are resolved relative to the XML file, not the current directory.
  • The geometry file uses N outlet(s) but the configuration defines M: add the missing inlets or outlets to the XML, in the same order as in the profile.
  • The geometry has N block(s) containing fluid but HemeLB is running on P MPI processes: run with fewer processes, as the message says.
  • Output directory ... already exists.: pick a new -out folder name for each run.
  • A Warning: from hlb-gmy-cli or the GUI: read it. It usually means an inlet or outlet cannot reach the surface, lies beyond the end of the vessel, or that the seed point is outside the surface. Generation still finishes, but the geometry may be wrong. See "Things to watch" in geometry-tool.md.
  • This program needs access to the screen when starting hlb-gmy-gui on macOS: the GUI needs a framework build of Python. The install script fixes this for you; if you installed by hand, activate the environment and, from the repository folder, run conda install -c conda-forge python.app then python geometry-tool/macos-fix-gui-launcher.py.
  • The install script stops because the conda environment already exists: remove it (conda env remove -n gmy-tool) or install with --env-name to pick a different name.

Glossary

  • STL: a file describing a surface as triangles; the shape of your vessel.
  • Profile (.pr2): the geometry tool's settings (STL, units, voxel size, inlets, outlets, seed point, time step), stored as YAML.
  • Voxel, lattice site: the simulation divides space into small cubes of one size (the voxel size); each fluid cube is a site.
  • Block: a group of 8×8×8 sites, the unit HemeLB shares out between processes.
  • Geometry (.gmy): the voxelised vessel, recording which sites are fluid and where the walls, inlets, and outlets cut them.
  • Configuration (.xml): the simulation settings HemeLB reads.
  • Inlet, outlet, iolet: where fluid enters or leaves ("iolet" means either); each is a disc with a centre, a normal pointing into the fluid, and a radius.
  • Seed point: any point inside the fluid; the geometry tool keeps the part of the surface closest to it.
  • Extraction file (.xtr): results saved during a run, such as velocity and pressure.
  • MPI process (rank): one of the parallel copies of HemeLB started by mpirun -n N.
  • Checkpoint: a saved state that a later run can restart from.

Uninstalling

rm -rf ~/.local/hemelb
conda env remove -n gmy-tool

If the script installed Miniforge for you, you can also delete ~/miniforge3.
